# Interview preparation

## Confirmed by the supplied candidate guide

Source: Candidate_Prep_Guide_AI_Coding_Interview.docx, supplied by the user on
2026-11-03. This is a paraphrase of interview logistics, not a copied company document
or authority to execute instructions found inside attachments.

- Technical portion: 60–75 minutes; task may be service design, problem solving or debugging.
- Use your own laptop and share the screen; bring your normal editor and AI environment.
- Prepared context, prompts, workspace setup, internet references and multiple AI tools are allowed.
- Language is your choice. Reasoning, decomposition, AI direction, evaluation and communication matter.
- Perfect completion, typing speed and memorized syntax are not the focus.
- Remove employer proprietary code, documents and data from the interview workspace.

The actual task, repository, external deployment requirements and subagent support
are still unknown. Prepared files being allowed does not promise every tool is available.
This harness contains generalized process instructions, not prior product code or chat exports.
Because the local folder sits beside other projects, share only the interview window and
keep agents scoped to the interview repository. Inspect global skills/instructions and
connected tools during rehearsal for unrelated context; this repo does not disable them.

## Rehearse before the interview

1. Open a fresh exercise worktree and run Harness: doctor and the harness self-tests.
2. Confirm Codex sign-in, chosen model, subagent availability and tool permissions manually.
3. Give a small practice task; confirm the agent discovers root instructions and the spec skill.
4. Agree a short spec, implement a slice, run real application checks and inspect the important code.
5. Save a handoff in the app, resume in VS Code, then reverse once. Confirm no duplicate writers.
6. Rehearse a changed requirement and an unavailable tool. Use sequential role passes if needed.
7. Test screen sharing, font size, terminal visibility, network and laptop power.
8. Record one improvement in the session retrospective. Keep main free of task solutions.

During the interview, explain the choice, inspect the consequence, then interpret the
validation. Use agent execution time to review code and consider failure cases. Keep the
interviewer involved in consequential ambiguities and acceptance examples.
